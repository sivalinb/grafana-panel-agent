# Contributing

Run the unit suite before proposing a change. For changes affecting query execution, rendering, dashboard saves or review behavior, also run the real demonstration and browser test.

Good next contributions include browser contracts for transformations, library-panel ownership, Grafana's newer dashboard resource APIs, individual reviewer identities, additional diagnosis tools, and deployment-time dashboard contract checks.

Keep executable repair policies explicit and constrained. An AI explanation or a nonempty query result alone is not authorization or semantic validation. New repair classes need tests for rejected approvals, changed revisions, scope preservation, failure and recovery.

Do not contribute production telemetry, real credentials, private dashboard exports or user browser profiles. Public demonstration evidence must be synthetic and clearly labeled. Third-party components keep their original licenses.
